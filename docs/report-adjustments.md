# 青龙报告与升级预估调整

基线：`80713b8262d21467fcad70086c38e6e22d13a744`。用户要求：青龙不做“任务总次数统计”；资产变化的上次记录时间归纳到最后一行；当前积分之后增加仿 Reference 的升级预估。沿用项目 Functional Programming 与 Modular 范式。

## 行为要求

1. 青龙入口明确向运行器传入 `collect_task_summary=False`；流程跳过该统计的查询，报告不展示该部分。标准入口默认行为保持不变。此参数是入口运行策略，不新增用户配置键，不影响通知模块。
2. 历史资产差额行只展示数值，上次记录时间在该报告末行汇总。多个时间须按对应资产分组，避免将暂缺字段保留的旧基准误标为新时间；首次记录仍明确表示没有历史基准。历史存储保持每字段真实采集时间。
3. 当前积分块之后、任务概况之前展示升级预估。使用 Reference 门槛 `0, 3, 10, 35, 70, 120, 200, 300, 450, 650, 900` 和每积分约 34 血液的换算；展示当前等级估计、下一等级门槛、积分缺口、所需血液与现有血液缺口。明确这是参考规则下的估算，不能承诺兑换后一定升级，也不追加兑换动作。
4. 缺失或非法积分不当作零；血液缺失不判断足够与否。精确门槛按已进入该档计算；达到参考表最高档后不预测下一档或声称论坛真正满级。支持千位分隔符与无单位积分，包括零。
5. 计算放在 `progression.py` 纯函数和不可变结果中，渲染放在 `reports.py`；HTML 解析仍放在 `parsers.py`。不新增中间实例状态，HTTP、等待和通知行为遵循原约定。

## 估算依据

门槛和血液换算来自本地 `Reference/GM-All-In-One/gamemale.py` 的 `LEVEL_THRESHOLDS` 与 `BLOOD_PER_POINT`。论坛[历史等级说明](https://www.gamemale.com/thread-8565-1-1.html)与[属性说明](https://www.gamemale.com/thread-8560-1-1.html)在本次公开访问时返回连接验证页，未据此确认当前规则。报告与文档均明确使用参考估算，实际以论坛为准。
