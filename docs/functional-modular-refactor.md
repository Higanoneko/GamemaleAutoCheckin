# 函数式与模块化流程重构

用户要求开发遵守 Functional Programming 与 Modular 范式。重构基线为 `1b0e74b`；本轮范围集中于刚实现的日常流程，保持现有用户功能、配置别名、客户端入口与青龙通知行为。

## 具体要求与实现

- **纯逻辑与 IO 分离。** `task_plan.py` 接收不可变 `DailyTaskOptions`，纯计算不可变任务计划；不依赖客户端、网络、时间、日志或文件。
- **模块职责明确。** `workflow.py` 执行任务计划、处理资产读取与社交后续动作、组合报告；`daily_tasks.py` 保留现有 `execute_all_tasks()` 入口及签到、抽奖请求动作。页面解析继续使用 `parsers.py`，资产计算使用 `assets.py`，报告使用 `reports.py`。
- **以数据流替代闭包共享状态。** 删除捕获可变 `outcomes` 等中间数据的嵌套编排函数；使用冻结数据类、元组和 `dataclasses.replace` 返回新运行数据，不新增中间实例属性。
- **依赖注入。** 编排函数显式接收客户端与日志互动函数，复用真实请求和离线假实现；HTTP 仍经 `_send_request`，等待仍经 `_sleep`。
- **保留行为。** 完整模式在互动之后领奖；在线检查和资产模式只查询资产；仅挂机模式不查询资产。旧配置别名和主动禁用继续生成跳过结果。停止后不执行后续动作或末尾采集；未知兑换结果不覆盖资产历史。
- **兼容接口。** `execute_all_tasks()` 仍返回 `AccountRunResult`；单项签到、抽奖仍返回 `TaskResult`。青龙通知仍使用原有回调。

## 验证方式

通过既有客户端接口 `execute_all_tasks()` 验证流程，不依赖计划内部结构。补充停止、旧别名禁用与多次运行结果隔离回归，保留互动后领奖、只读查询和资产采集有效性用例。类型检查覆盖新计划与编排模块；最终全套离线测试封锁网络连接。规范与规格由独立审查代理分别检查。
